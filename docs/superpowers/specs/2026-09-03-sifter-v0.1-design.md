# SIFTER v0.1 Design Specification

Date: 2026-09-03  
Status: Approved architecture; implementation not yet started

## 1. Purpose

SIFTER (Spectral Inference using Fourier Transforms for Energy Resolution) is a local-first scientific Python application for decomposing one-dimensional spectra. Given an `x` axis and measured intensity, v0.1 will:

1. validate and normalize the input representation without altering measured intensities;
2. propose plausible Gaussian, Lorentzian, and Voigt peak models;
3. fit every candidate to the original-domain data with constrained multistart least squares;
4. rank valid candidates with BIC by default while also reporting AICc;
5. report residual, uncertainty, Fourier, and identifiability diagnostics; and
6. expose the same engine through a Python API and a local Streamlit GUI.

The governing scientific rule is:

> Fourier-domain evidence may initialize and diagnose a fit, but only the original measured data determine fitted parameters and model scores.

SIFTER will not deconvolve, sharpen, or Fourier-filter a spectrum and then fit the altered signal.

## 2. Scope and success criteria

Version 0.1 targets a single spectrum with one independent coordinate and one intensity series. The coordinate may represent energy, Raman shift, wavelength, frequency, or another monotonic physical axis.

The release succeeds when a fresh user can install SIFTER, launch `sifter-gui`, load an arbitrary two-column synthetic spectrum, run automatic analysis without writing code, inspect the recommended decomposition and competing candidates, and export a reproducible result. CI must demonstrate reliable ground-truth recovery for identifiable, easy-to-moderately overlapping synthetic peaks. No super-resolution claim is made.

The following are explicitly out of scope:

- neural networks, Bayesian nested sampling, and reversible-jump MCMC;
- Prony, ESPRIT, and matrix-pencil peak recovery;
- two-dimensional spectra or simultaneous global fitting of multiple spectra;
- technique-specific XPS, Raman, photoluminescence, or asymmetric line shapes;
- GPU acceleration, remote services, accounts, telemetry, or databases;
- fitting deconvolved or otherwise sharpened data; and
- claims of reliable recovery below empirically validated resolution limits.

## 4. Core data contracts

### 4.1 Spectrum

`Spectrum(x, intensity, *, x_name="x", x_unit=None, intensity_name="intensity", metadata=None)` is an immutable validated value object. It stores one-dimensional, finite, equal-length floating-point arrays and descriptive metadata.

Validation rules are deterministic:

- at least eight observations are required for automatic fitting;
- NaN and infinite values are rejected with indexed error messages;
- descending coordinates are reversed; otherwise unsorted coordinates are rejected;
- duplicate coordinates are rejected rather than silently averaged;
- constant `x`, constant intensity, and all-zero intensity are rejected;
- negative intensities are allowed because background subtraction can create them;
- nonuniform spacing is allowed for real-domain fitting and recorded as a grid diagnostic; and
- input arrays are copied or made read-only so downstream work cannot mutate the observation.

The stricter eight-point minimum replaces the illustrative three-point failure case: three points must fail, and eight is the explicit public contract for v0.1.

### 4.2 Model specification

`ModelSpec` is a serializable declaration of peak count, peak family, baseline order, starting values, and parameter bounds. Version 0.1 candidates use one shared line-shape family per model (for example, four Voigt peaks), not arbitrary per-peak mixtures. This bounds the search space and keeps model comparison interpretable.

Peaks are canonically ordered by center before results or parameters are exposed. Optimizer-internal order is never part of the public contract.

### 4.3 Result schema

`FitResult` contains:

- `schema_version="sifter.fit_result.v1"`;
- an immutable summary of input metadata and analysis settings;
- the recommended candidate and an ordered candidate-comparison table;
- component parameters, bounds, standard errors, and confidence intervals when available;
- fitted signal, baseline, component curves, and residuals on the input grid;
- RSS, RMSE, parameter count, observation count, AICc, BIC, and residual diagnostics;
- Fourier diagnostics with applicability and quality flags;
- structured warnings with stable codes, severity, and human-readable context; and
- reproducibility metadata including SIFTER version and random seed.

Convenience methods are `plot()`, `to_dataframe()`, and `to_json()`. JSON output contains numeric data and provenance, not rendered figures. Non-finite values are encoded as `null` with a corresponding warning rather than emitted as non-standard JSON.

## 5. Line-shape conventions

All peak amplitudes use integrated area, not height:

- Gaussian parameters: area `A`, center `mu`, standard deviation `sigma`;
- Lorentzian parameters: area `A`, center `mu`, half-width at half-maximum `gamma`;
- Voigt parameters: area `A`, center `mu`, Gaussian `sigma`, Lorentzian `gamma`.

Profiles are normalized on the infinite mathematical domain, with the Voigt profile evaluated through `scipy.special.wofz`. Truncation by a finite observed window is not renormalized because doing so would make area depend on the acquisition window.

Constraints are `A >= 0`, positive widths, and centers within the observed coordinate range. Numerical lower width bounds are derived from grid resolution and coordinate span rather than machine epsilon. Upper width bounds prevent a peak from becoming an unconstrained surrogate baseline.

## 6. Baseline policy

The joint model is the sum of a baseline and peak components. Supported baseline candidates are constant, linear, and quadratic polynomials. An asymmetric least-squares baseline may provide an initializer or an explicitly selected preprocessing estimate, but automatic v0.1 scoring always evaluates the final joint model against original intensities.

Automatic mode favors low baseline complexity by including baseline coefficients in the information-criterion parameter count. Quadratic baselines are considered only when the data volume supports AICc and the simpler baseline candidates leave structured low-frequency residuals. SIFTER reports a degeneracy warning when a broad component is strongly confounded with the baseline.

Coordinates are centered and scaled internally for polynomial conditioning. Exported coefficients include the transformation needed to interpret them on the original axis.

## 7. Candidate detection and generation

Candidate detection combines weak, independent clues:

- `scipy.signal.find_peaks` prominence and width;
- peaks in one or more smoothed representations;
- zero crossings and extrema in smoothed derivatives; and
- Fourier characteristic-spacing clues when those diagnostics are applicable.

Detection outputs ranked center proposals and quality annotations, not a final peak count. Smoothing affects initialization only and never the fitted observations.

Candidate generation is deterministic for a fixed configuration and seed. Let `N0` be the consensus initial count. Automatic mode evaluates all supported counts from one through `min(max_peaks, N0 + 2)`, ensuring simpler alternatives are never omitted. If no reliable peaks are detected, it still evaluates one-peak candidates. Each requested line-shape family is crossed with eligible baseline orders. Duplicate specifications are removed before fitting.

The default `max_peaks` is six. The engine estimates the number of fits before execution and the GUI warns when an expanded search or thorough uncertainty mode is likely to be slow.

## 8. Fourier diagnostics

Fourier analysis operates on baseline-adjusted data for diagnostics and initialization only. The result records the baseline estimate used for the diagnostic.

For a sufficiently uniform coordinate grid, SIFTER computes a windowed real FFT and fits robust linear models to valid positive-frequency portions of the magnitude envelope:

```text
Lorentzian-like: log|F(k)| = C - a|k|
Gaussian-like:   log|F(k)| = C - b k^2
Voigt-like:      log|F(k)| = C - a|k| - b k^2
```

Near-zero bins, noise-floor bins, and bins invalidated by the window response are excluded. Envelope models receive goodness-of-fit and usable-frequency-range diagnostics; their labels are tendencies, not categorical proof of a physical line shape.

If coordinate-spacing variation exceeds a documented tolerance, v0.1 does not silently apply an ordinary FFT. The default behavior is to mark Fourier diagnostics unavailable while continuing real-domain fitting. An opt-in diagnostic-only interpolation onto a uniform grid may be added behind an explicit setting, with the interpolation recorded in the result. Lomb-Scargle and nonuniform FFT methods are outside v0.1.

Autocorrelation and Fourier-magnitude features may expose candidate spacings. The UI and API call these `Fourier candidate spacings`; they never assert a peak count.

## 9. Fitting and optimization

Each candidate is fitted with `scipy.optimize.least_squares`. Residuals are defined in the original intensity domain. Version 0.1 supports unweighted least squares and optional user-supplied positive per-point standard deviations; when standard deviations are supplied, residuals are divided by them.

Multistart generation perturbs valid detection-based centers, widths, and areas using a seeded NumPy generator. It also includes at least one evenly spaced fallback initialization. A start is valid only if it satisfies all bounds. The best converged solution by objective value is retained, with convergence details preserved.

The public orchestration function is:

```python
from sifter import Spectrum, autofit

spectrum = Spectrum(x, intensity)
result = autofit(
    spectrum,
    max_peaks=6,
    shapes=("gaussian", "lorentzian", "voigt"),
    fourier=True,
    random_seed=42,
)
```

One candidate's numerical failure does not abort the analysis. It becomes a failed comparison-table row with a stable failure code. The complete analysis fails only if input validation fails or no candidate yields a valid fit.

## 10. Model scoring and recommendation

For `n` observations, `p` freely fitted parameters, and residual sum of squares `RSS`, unweighted fits use the Gaussian maximum-likelihood form up to constants common to all candidates:

```text
AIC  = n * log(RSS / n) + 2p
AICc = AIC + 2p(p + 1) / (n - p - 1)
BIC  = n * log(RSS / n) + p * log(n)
```

AICc is unavailable when `n <= p + 1`, and that candidate cannot be recommended in automatic mode. For fits with supplied standard deviations, scoring uses the corresponding Gaussian log-likelihood including scale terms common across candidates. The implementation documents and tests the exact convention.

The lowest valid BIC is recommended. AICc is always displayed when defined. SIFTER reports delta values but does not convert them into invented model probabilities. Alternatives with `delta BIC < 2` trigger an `AMBIGUOUS_MODEL_SELECTION` warning; the preferred model remains the BIC minimum with deterministic tie-breaking toward fewer parameters, fewer peaks, lower baseline order, then the configured shape order.

Reduced chi-squared is reported only when meaningful measurement uncertainties were supplied. Without them, the UI labels the corresponding quantity as residual variance rather than reduced chi-squared.

## 11. Uncertainty and identifiability

Fast uncertainty uses a Jacobian-based local covariance approximation when the Jacobian has adequate rank and residual degrees of freedom. The result clearly labels this approximation and omits intervals when assumptions fail.

Thorough mode uses residual bootstrap refitting with user-selectable 100, 250, or 1000 replicates and a recorded seed. Bootstrap failures are counted and reported; intervals are withheld if the successful fraction falls below a documented threshold.

Structured diagnostics warn when:

- centers are nearly coincident relative to fitted width;
- a width or center is near a bound;
- an area collapses toward zero;
- the Jacobian or covariance is rank-deficient;
- parameter correlations are extreme;
- baseline and broad-peak terms are strongly confounded;
- the selected model is statistically ambiguous; or
- the acquisition window truncates a material fraction of a fitted component.

Warnings describe evidence and consequence without claiming that a fit is physically wrong. Thresholds are centralized configuration values and covered by unit tests.

## 12. GUI and local operation

Streamlit is the v0.1 GUI. The `sifter-gui` console command starts a local process and opens the local application in the user's browser. SIFTER itself sends no spectrum, fit result, analytics, or telemetry to a remote service.

The workflow has four stages:

1. upload CSV, TXT, or DAT and preview delimiter/header inference;
2. select `x` and intensity columns and confirm units or labels;
3. choose automatic defaults or advanced settings, then explicitly start analysis; and
4. inspect the recommendation, alternatives, plots, warnings, and exports.

Default controls enable Gaussian, Lorentzian, and Voigt candidates, use at most six peaks, allow simple automatic baselines, enable Fourier assistance, use covariance uncertainty, and use a fixed displayed seed.

The results view presents:

- recommended peak count, family, baseline, BIC, and AICc;
- the ordered delta-BIC comparison table including failed candidates;
- raw data with total fit and individual components;
- residuals against the coordinate axis;
- Fourier magnitude/envelope plots when applicable;
- a parameter and uncertainty table; and
- prominent identifiability and applicability warnings.

Exports include a versioned JSON result, a flat CSV peak table, and publication-neutral PNG figures. Exported artifacts are generated only after an explicit user action.

## 13. Input/output and privacy

Loaders infer comma, tab, semicolon, or whitespace separation from a preview and require the user or caller to resolve ambiguous columns. Parsing errors identify the line and likely remedy. The core API accepts arrays directly and has no file-system dependency.

The public repository contains only source, documentation, deterministic generators, and synthetic examples. Root-level `data/`, `private/`, `results/`, `outputs/`, `reports/`, and `benchmark_results/` are ignored. Generated `*.fit.json`, `*.fit.csv`, and `*.fit.png` files are ignored by default.

Existing files under the local `data/` directory are treated as private experimental inputs: they are not inspected for the design, staged, uploaded, used in tests, or mentioned by name in public artifacts.

No token, credential, machine-specific path, source data, or copied input values may appear in logs or serialized metadata. Error messages may include a user-selected basename locally but tests must verify that absolute paths and data rows are not leaked.

## 14. Synthetic data and benchmarks

`sifter.synthetic.make_spectrum` is the single source of deterministic synthetic fixtures for tests, examples, screenshots, and benchmarks. It accepts explicit line shapes, baseline parameters, grid definition, Gaussian noise or no noise, target SNR, and seed, and returns both a `Spectrum` and ground-truth metadata.

Public benchmark generators sweep peak separation divided by FWHM, SNR, amplitude ratio, Voigt composition, sampling density, and background slope. Raw benchmark outputs remain ignored initially. Benchmarks report recovery rates and parameter errors over repeated seeds rather than presenting one favorable realization.

## 15. Testing strategy

Implementation follows test-driven development. Test layers are:

- **Analytic unit tests:** numerical area normalization, FWHM conventions, translation invariance, parameter ordering, and finite-window behavior.
- **Fourier unit tests:** quantitative discrimination of pure Gaussian, Lorentzian, and Voigt envelope tendencies on well-sampled synthetic data; applicability behavior on nonuniform grids.
- **Validation tests:** NaN, infinity, unsorted and duplicate coordinates, too few observations, constant/all-zero intensity, nonuniform grids, negative intensities, and extreme baselines.
- **Recovery integration tests:** center, area, and width recovery within declared tolerances for identifiable one-, two-, and three-peak spectra.
- **Selection integration tests:** correct candidate wins under deliberately easy cases; ambiguous overlap produces a warning rather than an inflated claim.
- **Failure-isolation tests:** failed candidate fits remain visible without aborting a successful analysis.
- **Serialization tests:** deterministic versioned JSON round trips, standards-compliant non-finite handling, and privacy redaction.
- **GUI smoke tests:** synthetic upload, configuration, analysis, plots, warnings, and downloads all exercise the public API.
- **Performance regression tests:** bounded candidate sets complete within generous CI budgets; scientific correctness tests never depend on wall-clock microbenchmarks.

Randomized tests use explicit seeds. Numerical tolerances reflect discretization and optimizer behavior and are documented beside each assertion.

## 16. Packaging and compatibility

SIFTER uses a `src` layout and `pyproject.toml`. The initial supported Python range is 3.11 through 3.13. Runtime dependencies are NumPy, SciPy, pandas, Plotly, and Streamlit; development tooling includes pytest, pytest-cov, Ruff, and mypy. `lmfit` is not a core dependency.

Console entry points are:

```text
sifter-gui   launch the local Streamlit application
```

The import-level public surface for v0.1 is intentionally small: `Spectrum`, `autofit`, `FitResult`, and documented configuration/result types. Internal module paths are not compatibility guarantees.

CI runs linting, type checking, unit/integration tests, and package build checks on all supported Python versions. Release artifacts are a source distribution and pure-Python wheel. The project will use the BSD-3-Clause license, a permissive choice aligned with scientific Python distribution.

## 17. Delivery decomposition

This architecture is implemented in reviewable vertical foundations rather than by building the GUI first:

1. repository, packaging, privacy, and CI foundation;
2. `Spectrum`, line shapes, and deterministic synthetic generation;
3. baseline, detection, and Fourier diagnostics;
4. model specifications, fitting, multistart, and scoring;
5. result schema, uncertainty, and identifiability diagnostics;
6. end-to-end `autofit` orchestration and recovery/selection validation;
7. Streamlit GUI and export adapters; and
8. public benchmark generators, documentation, and release verification.

Each slice must have focused tests and leave the public API usable. Scientific validation precedes claims, screenshots, and release tagging.

## 18. Design decisions and rationale

- **Streamlit over PySide6 or notebook widgets:** it provides a usable local interface quickly while keeping the engine independent and replaceable.
- **SciPy least squares over a mandatory `lmfit` dependency:** the numerical core stays inspectable and lightweight.
- **Shared family per candidate:** it avoids a combinatorial mixed-shape search and yields understandable comparison tables.
- **BIC recommendation with AICc visibility:** it gives a conservative default without hiding alternative evidence.
- **Original-domain fitting:** it prevents preprocessing artifacts from becoming fitted evidence.
- **Synthetic-only public evidence:** it enforces privacy while providing known ground truth.
- **Versioned structured warnings and results:** consumers can automate around results without parsing display text.
- **Conservative Fourier applicability:** diagnostics fail closed when grid or signal quality does not support their assumptions.
