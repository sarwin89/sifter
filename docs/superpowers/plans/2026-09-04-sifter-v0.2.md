# SIFTER v0.2 implementation plan

> Execute on the long-lived `dev` branch. Use tests first, make small reviewable commits,
> and merge verified checkpoints back to `main` only at release gates.

**Goal:** Deliver a faster, transparent, scientifically conservative single-spectrum
workflow with robust text ingestion, at least ten-peak capability, staged and parallel
search, pre-fit diagnostics, windowed initialization, and optional related-spectrum help.

**Design:** `docs/superpowers/specs/2026-09-04-sifter-v0.2-design.md`

## Checkpoint 1: input reliability and result clarity

- Add explicit, backward-compatible table parsing options for delimiter, header mode, and
  leading rows.
- Reproduce malformed two-column TXT cases before changing the loader.
- Add GUI correction controls and structural preview.
- Add inline peak/uncertainty and residual-diagnostic tables.
- Add metric help and consistent interactive/static component rendering.
- Verify focused IO/GUI/export tests, then the full suite.

## Checkpoint 2: runtime baseline and bounded optimizer

- Add ignored runtime benchmark output and deterministic three- and ten-peak cases.
- Record starts, convergence, evaluations, termination, and elapsed time.
- Add explicit `max_nfev`, warm starts, and provisional budget-exhausted screening results.
- Prove provisional results cannot enter final exports.
- Raise the public and GUI peak ceiling to at least ten only after work is bounded.

## Checkpoint 3: staged adaptive search

- Add Fast, Standard, Thorough, and Exhaustive search modes.
- Compute preprocessing once and return a peak-detection summary.
- Build a detector-centered peak-count window with simple fallbacks.
- Expand at the count boundary and stop on repeated worsening or inadmissible peaks.
- Screen cheaply, retain shape/count/baseline diversity, and globally refine finalists.
- Compare Standard with Exhaustive on deterministic synthetic spectra.

## Checkpoint 4: parallel execution and progress

- Add spawn-safe top-level candidate workers and numerical thread limits.
- Generate deterministic seeds in the parent.
- Prove serial/parallel result equivalence.
- Add progress events for every search phase and bootstrap uncertainty.
- Add Windows Python 3.12 spawn smoke coverage.

## Checkpoint 5: pre-fit analysis and GUI progress

- Add cheap `SpectrumPreview` analysis without nonlinear multi-peak fitting.
- Show raw, global baseline, adjusted signal, and provisional centers immediately.
- Show FFT magnitude, log magnitude, envelope tendencies, units, grid validity, window,
  interpolation state, and candidate spacings.
- Replace the opaque fit spinner with parent-process progress reporting.

## Checkpoint 6: windowed progressive initialization

- Define resolved maxima, peak basins, window cores, halos, and merge/fallback rules.
- Fit independent windows in parallel and retain only core-owned peaks.
- Add residual-driven second-wave proposals without altering final observations.
- Assemble a bounded beam of global candidates and jointly refine on the full spectrum.
- Prove local scores are never summed or exported as global evidence.
- Test boundary peaks, long tails, broad+narrow mixtures, overlap, and global baselines.

## Checkpoint 7: multi-maximum component control

- Compute effective FWHM consistently for every line shape.
- Detect significant maxima within each fitted component's FWHM.
- Tighten/refit or split initialization when one component spans resolved maxima.
- Exclude persistent structural violations from ordinary final ranking.
- Add recorded advanced override for known broad physical bands.
- Test noise spikes, shoulders, true broad single maxima, and post-global-refinement checks.

## Checkpoint 8: measurement context and references

- Add temperature, laser power, and generic conditions with unit normalization.
- Prove context alone cannot change fitted parameters.
- Add versioned v2 result serialization and v1 compatibility tests.
- Add `FitReference` and reference-seeded candidates without removing ordinary candidates.
- Prove a wrong reference cannot force a model.

## Checkpoint 9: related-spectrum visualization

- Keep independently fitted results in the current local GUI session.
- Match tracks conservatively by center and FWHM with ambiguity reporting.
- Plot center, FWHM, and area against one selected condition.
- Do not introduce automatic temperature/power physics.

## Checkpoint 10: benchmark, documentation, and release

- Benchmark 1, 2, 3, 5, 8, and 10 peaks across selected shapes, sizes, SNRs, and workers.
- Record Standard-versus-Exhaustive disagreement honestly and tune retention from evidence.
- Meet the documented performance target on controlled hardware without wall-clock CI gates.
- Update the method, schema, privacy, benchmark, GUI, and search-mode documentation.
- Run Ruff, strict mypy, full coverage, build, installed-wheel GUI smoke, and privacy audit.
- Bump to 0.2.0 only at the release checkpoint; merge `dev` to `main`, tag, push, and verify CI.
